## 새로고침 버튼 2개 (다릅니다)

오른쪽 위에 버튼이 두 개 있습니다.

- **화면 새로고침** — 이미 받아둔 데이터를 다시 읽습니다. 즉시 끝납니다.
- **데이터 새로 받기** — GitHub Actions 페이지로 이동합니다. 거기서 `Run workflow` 를 누르면 실제로 최신 시세를 새로 수집합니다. 1분쯤 걸리고, 끝난 뒤 **화면 새로고침**을 누르면 반영됩니다.

자동 수집은 평일 한국시간 **오후 4시**(한국장 마감 후)와 **다음날 오전 7시**(미국장 마감 후) 두 번 돕니다.

## 내용을 바꾸고 싶을 때

`config.json` **한 파일만** 고치면 됩니다. GitHub에서 파일을 열고 연필 아이콘 → 수정 → `Commit changes`.

- `watchlist` — 관심종목
- `sectors` — 섹터 ETF 목록
- `cross_assets` — 크로스에셋 목록
- `ratios` — 상대강도 비율 (`num` / `den` 두 종목의 비율)
- `regime.growth` / `regime.inflation` — 어떤 비율을 성장축·물가축 판단에 쓸지
- `regime.lookback_days` — 몇 거래일 변화를 볼지 (기본 63일 ≒ 3개월)
- `news_queries` — 뉴스 검색어

`config/calendar.json` 은 경제 캘린더 일정입니다.

## 레짐 점수를 어떻게 계산하나

메릴린치 인베스트먼트 클락을 시장 가격으로 옮긴 방식입니다.

1. 각 비율의 **최근 63거래일 변화율**을 구합니다.
2. 그 값을 지난 1년치 63일 변화율들의 **RMS(제곱평균)** 로 나눠 정규화합니다 — 원래 많이 흔들리는 비율은 자동으로 점수가 눌립니다.
3. ±100 으로 자릅니다.
4. 성장축 4개, 물가축 2개의 평균이 4분면 좌표가 됩니다.

평균을 빼지 않는(mean-centering 없는) 방식이라, **꾸준히 오르는 추세는 계속 플러스로 잡힙니다.** 백분위 방식이면 추세장에서 "횡보"로 나오는 문제가 있어 일부러 이렇게 했습니다.

> 4분면은 예측이 아니라 **시장 가격이 지금 무엇을 반영하고 있는지의 요약**입니다. '유리했던 쪽'은 역사적 경향이지 보장이 아닙니다.

## 구조

```
.github/workflows/update.yml   시세 수집 스케줄 (GitHub Actions)
scripts/collect.py             수집 스크립트 → data/latest.json 생성
config.json                    ★ 이 파일만 고치면 됩니다
config/calendar.json           경제 캘린더
data/latest.json               수집된 데이터 (자동 생성, 직접 고치지 마세요)
index.html                     화면 전체
```

서버가 없습니다. GitHub Actions가 시세를 받아 `data/latest.json` 에 커밋하고, GitHub Pages가 `index.html` 을 그대로 서빙합니다. 브라우저는 그 JSON 하나만 읽습니다.

데이터 출처: 야후 파이낸스(yfinance 배치) → 네이버 금융(국내 지수) → stooq 순으로 대체합니다. CNN 공포탐욕지수, DART 전자공시, 구글 뉴스 RSS.

## DART 전자공시 키

저장소가 **공개(Public)** 이므로 API 키를 파일에 절대 적지 마세요. GitHub Secrets에만 넣습니다.

`Settings → Secrets and variables → Actions → New repository secret`
- 이름: `DART_API_KEY`
- 값: opendart.fss.or.kr 에서 받은 인증키

키가 없어도 전자공시 화면만 비고 나머지는 정상 동작합니다.
